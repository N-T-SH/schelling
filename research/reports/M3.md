# M3 Model v0: report

**Result:** the untrained model, typed heads, Predictor API and population sampler are built and pass their tests on the tiny backbone and, for save, reload and batching, on the real ModernBERT-base. GitHub CI is green (with CPU-only torch). No open decision points.

## What was built

- `src/schelling/model/`: `SchellingConfig` (embeds the backbone config, three calibration temperatures, token budgets), `SchellingModel` (shared encoder, Noul, Choice and Score heads, `from_backbone` to wrap a pretrained encoder), `heads.py`. These files use relative imports only so they can be copied to the Hub and loaded with `trust_remote_code`.
- Heads: Noul is an MLP to a sigmoid; Choice scores each option text against the context with shared weights and masks padded options; Score is a CORN-style ordinal head whose survival function is a cumulative product of conditional probabilities, so it is monotone by construction.
- `src/schelling/infer/`: `Predictor` (`from_pretrained`, `save_pretrained`, `decide`, `decide_batch`, `encode_person`), `text.py` (person encoder v0: attributes plus the last k history items, oldest dropped first, the question never cut), `simulate.sample_population`.
- CLI: `schelling simulate --model --persons --request --out`.
- Tooling: CI installs the `train` extra from the CPU-only PyTorch index on Linux.

## Problems found and how they were handled

1. **A test suite that passed for the wrong reason.** With transformers 5, `BertTokenizer(vocab_file=...)` silently ignored the file and mapped every word to the unknown token, so every option looked identical and the model returned exactly uniform probabilities; the permutation-invariance tests passed vacuously. Found when a temperature test failed. Fixed (the tokenizer now takes a vocabulary mapping), and a non-degeneracy test was added so this cannot recur unnoticed.
2. **torch and LightGBM crash when loaded in one process on macOS** (each bundles an OpenMP runtime). The B3 tests now live in `tests/gbm`, which the main suite ignores and a wrapper test runs in a fresh interpreter; LightGBM is imported lazily. Production runs use one or the other. No change to B3 itself or to any M2 result.
3. **Process slip:** I wrote the model skeleton before the tests, against the rule of tests first. The tests were then written and run against it, and the catch in item 1 came from them, but the order was wrong.

## Deviations and choices to review

- `Predictor.encode_person` returns the serialised person text in v0; cached encoder states arrive with person encoder v1 in M5 (stated in the docstring).
- On the real ModernBERT-base, batch and single inference agree within 1e-4, not 1e-5 (the 1e-5 bound holds on the tiny model). Likely floating-point differences from padding in attention; worth knowing before M5 caching.
- mypy overrides relax two strict checks for the model and predictor modules only, because transformers ships partial type information.
- Not done: ModernBERT-large batching and saving were not tested (it loads and runs forward); no push to the Hub (needs approval).
